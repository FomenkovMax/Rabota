# AGENTS.md — правила работы над проектом

## Жёсткие правила (нарушать нельзя)

1. **Не выдумывать данные**: ставки, продукты, акции, URL, даты, цитаты. Нет данных — поле пустое, статус «неизвестно».
2. **Демо ≠ реальность**: тестовые фикстуры живут только в `tests/`, помечены как синтетические и никогда не попадают в БД/бота/отчёты.
3. **ЛНР**: общероссийская доступность не доказывает доступность в ЛНР. `AvailabilityStatus.CONFIRMED` — только при цитате из документа. Иначе `NOT_CONFIRMED`/`UNKNOWN`.
4. **Источники**: только официальные домены банка (проверяет `RegistryConfig`). Не обходить капчи, антибот и `robots.txt` — фиксировать `BLOCKED`/`ROBOTS_DISALLOWED` и показывать неполноту.
5. **Деньги считает код**, не LLM. LLM только извлекает структуру из текста и пишет выводы по уже посчитанным числам; извлечённое значение должно иметь цитату-доказательство.
6. **Секреты** — только через окружение/`.env` (в git не попадает). Внутренние банковские данные во внешние API не отправлять.
7. **Ручной импорт** — единственный путь для сайтов, закрытых защитой: документ помечается `origin=manual_import`, дата — со слов человека; внутренние данные банка не импортируем.
8. **Неудачи не прячем**: каждая попытка загрузки пишется в `fetch_attempts`, неполнота видна в `/status` и отчётах.
9. Внешние действия (публикация, деплой, PR, рассылки) — только после согласования с владельцем.

## Архитектура в двух словах

`registry` (конфиг → БД) → `sources` (адаптеры: fetch+parse) → `db` (документы, снимки, изменения) → analytics/AI → `reports` / `bot`. Подробнее — `docs/ARCHITECTURE.md`.

## Процесс

- Этапы — в `PLANS.md`. После каждого: тесты, правка ошибок, обновление README/PLANS, коммит.
- Не заявлять «работает» без фактической проверки; в README есть колонка «проверено / не проверено».
- Новый банк = запись в `config/banks.yaml` + (при необходимости) адаптер, зарегистрированный через `@register_adapter`.
- Изменения схемы — только через Alembic; `pytest tests/test_migrations.py` должен проходить (проверяет, что модели и миграции не расходятся).
- Стиль: Python 3.12, типы, async, комментарии на русском там, где объясняют «почему».

## Качество и безопасность (этап 7)
- Перед коммитом: `ruff check .` и `pytest`. Зависимости — через `pyproject.toml`; после изменения обновить `requirements.lock` из **чистого** окружения (так находятся недостающие зависимости).
- Любые данные с чужих сайтов — недоверенные: экранировать в HTML/Telegram, строки в XLSX — только текстом, пути и URL — проверять по официальным доменам.
- Новые поверхности (inline/callback в боте, новые эндпоинты API, вызовы внешних API) — сначала дополнить `docs/security.md`.
- Комментарии в `.env.example` — только отдельными строками.
