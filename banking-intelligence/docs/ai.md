# AI-извлечение (этап 3)

⚠️ **Статус: реализовано и проверено на ПОДСТАВНОМ клиенте. Реальная модель не вызывалась ни разу** (нет ключа; включение — решение владельца). Класс `OpenAIClient` написан по памяти API и не проверялся.

## Что делает
Из сохранённых страниц продуктов (`detail:*`) модель извлекает **структуру условий**: капитализация, пополнение, снятие, досрочное расторжение, выплата процентов, срок, минимальная/максимальная сумма, упоминания ЛНР. Расчёты и ставки модель **не** делает и не меняет: ставки берутся только из правил, деньги считает код.

## Как не доверять модели (всё проверяет код, `ai/verify.py`)
1. Каждый факт обязан иметь `quote` — **дословную** цитату; она должна быть в том же тексте, что отправлен модели (нормализация пробелов/регистра/кавычек, правки слов не допускаются).
2. Цитата 8–400 символов и **по теме поля** (для «капитализации» — слово «капитализ…» и т.д.).
3. Для срока и сумм все числа значения должны присутствовать в цитате.
4. Цитаты, похожие на указания модели («игнорируй…», «верни…», «ты — …»), отбрасываются (защита от prompt injection).
5. Нарушение схемы JSON, ошибка сети/API — фиксируются, сбор не падает. Всё отброшенное сохраняется в `rejected` с причиной.
6. **ЛНР**: статус `confirmed` только при проверенной цитате, где явно названа ЛНР/Луганск **и** сказано, что продукт доступен. Упоминание региона в строке про телефон/уведомление отбрасывается даже если модель назвала его подтверждением. Противоречивые цитаты → `unknown`.

## Как данные попадают в расчёты
Снимок `kind=ai_conditions` (`extractor=llm:<модель>`, цитаты в `evidence`). AI **только заполняет пробелы** (срок, сумма); значение, найденное правилами, не перезаписывается. Такой продукт помечен 🤖 / «часть данных — AI (цитата проверена)», в примечании — сама цитата. Пример на реальной странице: у вклада «Ключевой» (ВТБ) срока нет на карточке, на странице есть «6–36 мес. Срок» — после извлечения вклад участвует в сценариях.
Капитализация и прочие булевы факты сохраняются справочно; в расчёт дохода пока **не** входят (нужна периодичность капитализации).

## Защита данных и расход
- Отправляется только текст **публичной** страницы из сохранённых документов, домен которых совпадает с официальным доменом банка (иначе документ пропускается). Внутренних данных банка в этом конвейере нет.
- Включение: `AI_ENABLED=true`, `AI_MODEL`, `OPENAI_API_KEY`, `pip install -e ".[stage3]"`. Без этого `bankintel ai-extract` выполняет **пробный запуск** (ничего не отправляется) и печатает, что было бы отправлено.
- Лимиты: `AI_MAX_DOCS_PER_RUN` (20), `AI_MAX_CHARS` (60 000 на страницу); кэш по хешу документа и версии подсказки — повторно тот же документ не отправляется. В логах только id документа и число символов, не содержимое.
- Приоритет: сначала продукты без условий, извлечённых правилами (сейчас — ВТБ).
- Оценка на реальных сохранённых страницах (пробный запуск 24.10.2026): 26 страниц, 20 за запуск ≈ 195 тыс. символов.

## Остаточные риски
- Инъекция, **не похожая на инструкцию** и размещённая на самой официальной странице, пройдёт механические проверки (цитата настоящая, по теме). Это требует компрометации сайта банка; ограничение ущерба: AI не трогает ставки, только заполняет пробелы, всё помечено и содержит цитату для ручной проверки.
- Булевы факты (пополнение: да/нет): проверяется цитата и тема, но **полярность** («можно» / «нельзя») код проверить не может — их нужно сверять глазами по цитате.
- Качество на реальной модели неизвестно: нужен прогон на размеченной выборке (хотя бы 10–15 страниц с ручной разметкой) перед тем, как полагаться на результат.
