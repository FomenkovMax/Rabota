# Эксплуатация

## Запуск
`docker compose up --build` (нужен `.env`: `BOT_TOKEN`, `ALLOWED_TELEGRAM_IDS`, **`POSTGRES_PASSWORD`**). Сервисы: db, redis, migrate, bot, api, worker, beat.

## Проверка состояния
| Что | Как |
|---|---|
| Жив ли API и БД | `GET http://127.0.0.1:8000/health` |
| Свежесть данных | `GET /health/data`: по каждому банку с подтверждёнными источниками — возраст последнего успешного сбора; `degraded`, если старше 2 интервалов мониторинга или сборов не было. Неудачные запуски данные не «освежают» |
| Состояние в боте | `/status` (последний сбор, последняя загрузка и её исход, число документов и продуктов) |
| Логи | `LOG_LEVEL`, `LOG_JSON=true` для JSON-строк; токены/ключи маскируются автоматически |

## Исходы загрузки (`fetch_attempts.outcome`)
`ok`, `http_error`, `network_error` (3 попытки с экспоненциальной паузой), `tls_error`, `blocked` (антибот/WAF — не обходим), `robots_disallowed`, `too_large`, `redirect_rejected`, `internal_error`.

## Очистка данных
`bankintel prune` — **план без удаления**; `bankintel prune --apply` — удаление. Параметры: `--keep-snapshots 20` (≥3), `--attempts-days 90`, `--documents-days 180`. Никогда не удаляются: последние снимки продукта по источнику, снимки из событий изменений, ссылочные и последние документы источников, документы ручного импорта. Рекомендуется раз в месяц, предварительно сделав бэкап БД.

## Бэкап (не автоматизирован)
Состояние = БД PostgreSQL + том `raw_data` (сырые документы). Минимум: `pg_dump` + архив тома по расписанию вне контейнера.

## CI
`.github/workflows/banking-intelligence.yml`: ruff, pytest на настоящих PostgreSQL и Redis, pip-audit по `requirements.lock`, сборка Docker-образа (проверка запуска не от root). ✅ Запускался в GitHub Actions на PR #1 и #2: jobs `test` и `docker` зелёные. Триггер — только `pull_request` с фильтром путей.

## Регрессия на реальных страницах
После смены вёрстки сайтов или правок адаптеров: `REAL_DOCS_DIR=<каталог сырых документов> pytest tests/test_real_documents.py` — проверяет, что на настоящих сохранённых страницах ПСБ/ВТБ по-прежнему разбирается ≥8 продуктов и у ≥80% распознана ставка.

## Что проверено в compose (24.10.2026)

Образ собран, стек поднят целиком: `migrate` (alembic + seed: 5 банков, 11 источников) → `api` (`/health` ok, `/health/data` degraded до первого сбора), `worker` (Celery готов), `beat`, `db`, `redis`. Процессы работают от uid 10001. Цикл `bankintel monitor` выполнен 4 раза по реальным сайтам: ПСБ, ВТБ, ЦМР — ok; Сбер и Генбанк — `failed` («нет активных источников»); условия страниц ВТБ — `partial` (нужен AI). Параллельный запуск отклоняется замком Redis. Изменений не зафиксировано (между запусками прошли минуты).

**Не проверено:** сервис `bot` (нужен `BOT_TOKEN`), уведомления в Telegram, срабатывание beat по расписанию (6 ч), обнаружение реального изменения на живом сайте.

**Оговорки среды проверки** (на обычной машине не нужны): HTTPS из контейнеров шёл через перехватывающий прокси песочницы, поэтому в образ подкладывался её CA (временный Dockerfile вне репозитория), а запросы к ПСБ/ВТБ из сети контейнера получали 503 от прокси — цикл запускался с `--network host` и явным прокси. Docker Hub отвечал 429 на частые скачивания базовых образов.
