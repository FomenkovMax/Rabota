# Мониторинг изменений (этап 6)

## Как это работает
1. **Цикл** (`cycle.py`, `bankintel monitor`): сбор по подтверждённым источникам (+ импортированные вручную документы) → страницы продуктов → поиск изменений → (опционально) уведомления.
2. **Расписание**: Celery beat раз в `MONITOR_INTERVAL_HOURS` (по умолчанию 6 ч) ставит задачу `bankintel.monitor_cycle`, её выполняет worker. Межпроцессный замок в Redis не даёт циклам идти параллельно; просроченные задачи в очереди отбрасываются (`expires`).
3. **Сравнение** (`monitor.py: detect_changes`): снимки текущего запуска сопоставляются с предыдущим запуском **того же источника**.

```bash
docker compose up --build            # db, redis, migrate, bot, api, worker, beat
bankintel monitor                    # один цикл вручную (с замком в Redis)
bankintel changes --days 7           # изменения из консоли
# локально без Docker:
celery -A bankintel.tasks worker -l info --concurrency 1
celery -A bankintel.tasks beat -l info --schedule /tmp/celerybeat-schedule
```
Бот: `/changes [дней]` (1–90, по умолчанию 7). Отчёты содержат раздел «Изменения за 30 дней» во всех форматах.

## Типы событий и значимость
| Тип | Когда |
|---|---|
| `changed` | поля карточки или условия страницы продукта отличаются от прошлого запуска |
| `new` | продукт впервые появился (значимость `rate`); вернулся после снятия с сайта (`rate`); появился на ещё одной странице (`info`) |
| `removed` | продукт исчез из всех источников (`rate`, продукт помечается неактивным и пропадает из сравнений); исчез с одной страницы, но есть на другой (`info`) |

Значимость: **rate** — ставка, базовая ставка, срок, сумма, валюта; **conditions** — строки условий со страниц продуктов; **info** — название, описание, ссылка, прочие параметры карточки. Рассылка в Telegram — только `rate` и `conditions`.

## Защита от ложных срабатываний
- Первый запуск по источнику — **базовая линия**: событий нет. Бот и отчёт прямо пишут «пока базовая линия», пока не было ни одного сравнения.
- «Продукт исчез» — только если страница в этом запуске загрузилась **и** разобралась. Сбой загрузки, блокировка или смена вёрстки (ошибка разбора) ничего не «удаляют» и видны в `/status`.
- Сравнение внутри одного источника: расхождения между страницами (например, срок «Сильной ставки» на странице вкладов и спецпредложений) изменениями не считаются.
- Повторный вызов `detect_changes` для того же запуска не создаёт дублей.

## Уведомления
По умолчанию **выключены**. Включаются `NOTIFY_CHANGES=true` при заданных `BOT_TOKEN` и `ALLOWED_TELEGRAM_IDS`; получатели — только пользователи из allowlist. Сбой отправки не прерывает цикл.

## Ограничения
- Каждый запуск добавляет новые снимки (хранение не ограничено — политики очистки пока нет).
- Изменения ВТБ в условиях продуктов не отслеживаются: условия ВТБ ещё не извлекаются (этап 3).
- Сайты Сбера и Генбанка недоступны сбору: события по ним возможны только после ручного импорта документов и написания адаптера.
- Один цикл занимает ~2,5 минуты (паузы между запросами); при интервале меньше нескольких минут задачи будут идти подряд.
- Docker-сервисы worker/beat/redis проверены только `docker compose config`; локально Celery + Redis проверены вживую.
