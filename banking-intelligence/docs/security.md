# Безопасность: аудит этапа 7 (24.10.2026)

Аудит выполнен по коду проекта: ручной разбор поверхностей атаки + автоматические проверки (ruff, pip-audit, поиск секретов по истории git, тесты). Это самопроверка автора, **не независимый аудит**.

## Модель угроз
- Недоверенный ввод: содержимое сайтов банков (HTML, названия продуктов, ссылки, редиректы), документы, внесённые вручную, аргументы команд бота.
- Доверенные: конфигурация (`config/*.yaml`, `.env`), пользователи из `ALLOWED_TELEGRAM_IDS`.
- Активы: токен бота, пароль БД, целостность данных в отчётах (отчёт вводит в заблуждение — тоже ущерб).

## Проверено, проблем не найдено
- Экранирование недоверенных названий в HTML-отчёте (Jinja autoescape; встроенный Plotly), SVG и в HTML-режиме Telegram — тесты с `</script><img onerror>` и `"><svg onload>`.
- SQL — только через SQLAlchemy с параметрами; `shell`/`eval`/`pickle` не используются.
- Доступ к боту: по умолчанию отказ всем; оба текстовых хендлера за allowlist-middleware.
- Секреты: в истории git нет токенов/ключей (regex-поиск по всем коммитам); единственный `.pem` — публичный сертификат; `.env` в `.gitignore`; секреты — `SecretStr`.
- Зависимости: `pip-audit` по `requirements.lock` — «No known vulnerabilities found» (на 24.10.2026).
- Парсеры: fuzz-тесты (тысячи случайных строк) и входы для катастрофического backtracking — укладываются в 2 с.

## Открытые риски и допущения (не устранены)
1. **Доверие к CA Минцифры** в процессе загрузчика: компрометация этого CA позволила бы подменять ответы банков. Смягчение: сертификат подключается только загрузчику, URL ограничены официальными доменами, редиректы — тем же сайтом. Остаточный риск принят владельцем; отпечаток сертификата надо сверить вручную (`certs/README.md`).
2. **Без аутентификации API и Redis** внутри compose: порты не публикуются (API — только `127.0.0.1`). Замок Redis — вспомогательный, не граница безопасности.
3. **Нет ограничения частоты команд на пользователя** в боте (есть глобальные блокировки на `/report`, `/refresh`). Команды доступны только allowlist-пользователям.
4. **Middleware доступа навешен только на сообщения.** Если появятся callback-кнопки/inline-режим, middleware нужно навесить и на них.
5. **AI-извлечение (этап 3) и prompt injection** — реализованы меры (дословные цитаты, фильтр «цитата похожа на указание», AI не трогает ставки, только заполняет пробелы, выключено по умолчанию; см. `docs/ai.md`). Остаточный риск и непроверенность на реальной модели описаны там же. Данные во внешний API уходят только по явному включению и только публичные тексты с официальных доменов.
6. Исходные документы на диске не шифруются (публичные страницы). Бэкапы БД/хранилища не настроены.
7. `requirements.lock` — набор для разработки и CI (включает инструменты); образ Docker ставит зависимости по диапазонам из `pyproject.toml`.
8. **Не проверялось**: реальный Telegram, открытие отчётов в MS Office (PowerPoint/Excel; через LibreOffice проверено). Docker-образ собран и стек поднят, GitHub Actions зелёный — см. `docs/operations.md`.
