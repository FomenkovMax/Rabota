# ЦМРБанк (адаптер `cmr`)

## Откуда данные
Страницы «Вклады» (`/person/person-deposit/deposit-calc/`) и «Накопительные счета» (`/person/person-deposit/deposit-account/`). Данные продуктов — **JSON внутри inline-скрипта** страницы (`deposites: {...}`, калькулятор на Vue): отдельных запросов к серверу страница не делает (проверено Playwright: из сети — только метрика). Поэтому **для сбора браузер не нужен**: обычная загрузка + разбор JSON (`sources/cmr.py`, без `eval`). Это надёжнее и легче Chromium в образе.

> Источники добавлены в `config/sources.yaml` как `active` по просьбе владельца («займись ЦМР»), но помечены «требует подтверждения» — подтвердите страницы или уберите.

## Что извлекается
Для каждого действующего продукта: название, аннотация, ссылка на PDF-условия, «До X %» (как на сайте), минимальная сумма, возможность пополнения/снятия, признак переменной ставки (по примечанию на странице) и **таблица ставок «сумма × срок»** (отдельно для выплаты «в конце срока» и «ежемесячно»). Пенсионный вариант вклада — отдельный продукт («Доход на максимум для пенсионеров»).

## Точная ставка вместо диапазона
Банк публикует ставку для конкретной суммы и срока, поэтому в сценариях сравнения (`/compare`) у ЦМР нет интервала: берётся ставка из таблицы банка (выплата в конце срока), доход = сумма × ставка × дни/365 — тем же методом, что у остальных банков. Срок сценария сопоставляется со сроком банка с допуском ±3 дня («12 мес.» = 365 дн. → «1 год» = 367 дн.), `max_sum` из данных банка учитывается как верхняя граница суммы (смысл поля на сайте не раскрыт — трактовка консервативная, видна в примечании к продукту).

## Роль Playwright (`tools/cmr_calculator_golden.py`)
Логика выбора ставки портирована на Python (`analytics/rate_tables.py: lookup`) по исходному коду калькулятора. Сверяется порт **с самим калькулятором на сайте**: скрипт проверяет `robots.txt`, открывает страницу с честным User-Agent, в самой странице перебирает сетку (9 сумм × 14 сроков × 3 способа выплаты × 3 набора фильтров «пополнение/снятие») и сохраняет результаты в `tests/fixtures/cmr_calculator_golden.json` (5 670 точек, 24.10.2026). `tests/test_cmr.py` требует **нуля расхождений** на всех точках.

Обновить эталон (после смены данных/логики на сайте):
```bash
pip install -e ".[stage2]"
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/путь/к/chrome python tools/cmr_calculator_golden.py --out tests/fixtures/cmr_calculator_golden.json
# и заново сохранить страницы-фикстуры (tests/fixtures/cmr_deposit_*.html)
```
Скрипт не нужен в продакшене и не входит в образ.

## Ограничения
- Тарифы по зарплатной карте и особые ставки не моделируются (берётся вариант «без льгот»); ежемесячная выплата и капитализация в сравнение не входят (в таблице они есть).
- PDF-условия продуктов не разбираются (ссылка сохраняется) — условия пополнения/снятия берутся из флагов таблицы; детали договора — нет.
- «ЦМР Резерв» — переменная ставка: в расчёте начальная.
- Доступность в ЛНР не подтверждена (на страницах не упомянута).
- Структура данных страницы может измениться: тогда разбор даст `parse_error` (сбор по ЦМР пометится неуспешным), а не «нет продуктов»; эталон и тесты покажут, что именно сломалось.
