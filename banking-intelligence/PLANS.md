# PLANS.md — поэтапный план

Статусы: ✅ сделано и проверено · 🚧 в работе · ⬜ не начато

## Этап 1 — Каркас ✅
Python-пакет, конфиг, модель данных, Alembic, реестр банков/источников, интерфейс адаптера, бот (`/start /banks /status` + заглушки остальных команд), allowlist, FastAPI `/health`, Docker Compose, pytest.
Не проверено: сборка Docker-образа, реальный Telegram.

## Этап 2 — Сбор данных ⬜
- `Fetcher`: httpx + учёт `robots.txt`, rate limit, User-Agent с контактом, сохранение `FetchAttempt` и `Document` (sha256, файловое хранилище), детект блокировок без обхода.
- Playwright — только для страниц, которым нужен JS, и только если robots/ToS позволяют.
- Обнаружение продуктовых страниц на официальных сайтах → **ручное подтверждение URL** (status `todo` → `active`).
- Celery + Redis, `/refresh`, PyMuPDF для PDF-тарифов.
- Реальные адаптеры банков по мере проверки структуры страниц.
- **Риск**: сайты банков могут быть недоступны из облачной среды/блокировать ботов — тогда фиксируем неполноту, а не подменяем данные.

## Этап 3 — AI-извлечение ⬜
Pydantic-схемы вклада/накопительного счёта/акции; LLM (OpenAI) возвращает JSON + дословные цитаты; валидатор проверяет, что цитата реально есть в документе; отбрасываем значения без доказательства. Определение доступности в ЛНР по тексту. Решение по отправке текстов во внешний API — согласовать.

## Этап 4 — Сравнение ⬜
Единые клиентские сценарии (сумма × срок × капитализация/пополнение), программный расчёт `Decimal` (проценты, капитализация, налог на доход где применимо), сравнение со Сбером, учёт доступности в ЛНР, `/compare /deposits /savings /promo`.

## Этап 5 — Отчётность ⬜
Единый проверенный набор данных → Plotly-дашборды → HTML (Jinja2), PDF (WeasyPrint), PPTX, XLSX. `/report`.

## Этап 6 — Мониторинг изменений ⬜
Снимки по расписанию, diff по `ProductSnapshot`, `ChangeEvent`, `/changes`, уведомления.

## Этап 7 — Усиление ⬜
Наблюдаемость, ретраи, тесты на реальных сохранённых документах, CI, ревью безопасности.
