# Промпт для аудита бота «Радар ЛНР»

Скопируй текст ниже в новую сессию Claude Code, открытую в папке проекта (`radar-lnr/`). Для повторных аудитов
(раз в месяц или перед крупным изменением) сравнивай новую оценку с предыдущей.

---

Ты — независимый аудитор. Проведи аудит проекта «Радар ЛНР» (папка `radar-lnr/`): Telegram-бот, который раз в 4 часа
читает публичные Telegram-каналы ЛНР, классифицирует посты LLM (через сторонний прокси-сервис), обогащает организации
по ИНН (DaData), считает ориентировочный финансовый эффект и присылает дайджест + PDF/HTML/Excel сотрудникам
ПАО Сбербанк (5 человек, закрытая группа). Работает в Docker на VPS за пределами РФ.

## Правила аудита
1. **Только факты.** Каждый вывод подкрепляй файлом и строкой (`путь:строка`), выводом команды или результатом
   теста. Не выдумывай уязвимостей и не хвали без доказательств. Чего не смог проверить — вынеси в раздел
   «Не проверено» и объясни почему.
2. **Запускай, а не только читай:** `uv run pytest -q --cov=radar`, `uv run python -m radar --help`,
   сборку образа (`docker build`), поиск секретов в репозитории и истории git (`git log -p -S`), проверку
   зависимостей на известные уязвимости (`uv pip list`, `pip-audit`, если доступно).
3. **Не меняй код и не трогай боевые данные.** Исправления только предлагай. Секреты (`.env`) не печатай и не
   копируй в отчёт.
4. **Не завышай оценки.** Оценка 8+ требует доказательств по каждому пункту критерия. Если сомневаешься —
   ставь ниже и объясняй.

## Что проверить (критерии с весами)
1. **Соответствие требованиям (20%)**: сверь с `README.md` и исходным ТЗ: сбор из t.me/s, категории 1–8,
   правило «LLM не выдумывает ИНН/суммы/имена», обогащение, оценка эффекта, дайджест ≤4096 символов, PDF/HTML/Excel,
   whitelist, `/report`, `/digest`, `/inn`, расписание 00/04/08/12/16/20 МСК, ночью без звука, токены в конце.
2. **Качество результата (20%)**: точность классификации и оценок важности, дедупликация (внутри запуска, между
   запусками, пересказы), сопоставление организаций с реестром (ложные совпадения!), правдивость фин. оценки
   (помечены ли заглушки). Есть ли способ измерить качество (размеченные данные, метрики)?
3. **Надёжность (15%)**: сбой одного канала/источника/LLM/DaData; ретраи и таймауты; блокировки и гонки
   (запуски одновременно); поведение при пустом балансе токенов, при перезапуске в момент слота, при росте базы;
   идемпотентность; потеря данных.
4. **Безопасность (15%)**: хранение и утечки секретов (логи, git, образ, `/proc`), whitelist и обход (группы,
   `@упоминания`), внедрение инструкций через тексты постов (prompt injection) и его последствия, XSS в HTML-дашборде,
   HTML-инъекции в сообщениях Telegram, SQL, SSRF (скачивание картинок), права файлов и контейнера, защита сервера
   (SSH, firewall), зависимости, лимиты на дорогие команды, приватность и соответствие требованиям банка (внешний
   прокси, зарубежный сервер, персональные данные руководителей).
5. **Качество кода и тесты (10%)**: читаемость, дублирование, обработка ошибок, типы; покрытие и **качество**
   тестов (проверяют ли они поведение или только «зелёные»); есть ли CI, линтер, pre-commit.
6. **Эксплуатация и наблюдаемость (10%)**: логи и ротация, метрики, оповещения «бот молчит», резервные копии,
   очистка базы, процесс обновления и откат, документирование эксплуатации (`README.md`).
7. **Продуктовая ценность и UX (5%)**: полезность дайджеста для задач Сбера, читаемость, шум, понятность команд.
8. **Документация (5%)**: актуальность README, `.env.example`, комментарии для новичка.

## Формат отчёта
1. **Итоговая оценка по 10-балльной шкале** (взвешенная) и оценка по каждому критерию (таблица: критерий, вес,
   балл, 1–2 строки обоснования с ссылками на доказательства).
2. **Находки**, отсортированные по серьёзности (🔴 критично / 🟠 важно / 🟡 желательно / 🔵 замечание). Для каждой:
   что, где (`файл:строка`), чем грозит (конкретный сценарий), как исправить (минимально), оценка трудоёмкости (S/M/L).
3. **Что сделано хорошо** (3–7 пунктов, с доказательствами).
4. **Топ-10 улучшений** по соотношению пользы к трудозатратам.
5. **Не проверено** и почему (например, нет доступа к серверу или боевым данным).
6. **План**: что исправить за неделю, за месяц, потом.

Пиши по-русски, простым языком: читатель — начинающий/средний разработчик на Python.
