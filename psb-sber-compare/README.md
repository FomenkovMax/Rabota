# Сравнение розничных продуктов Сбера с конкурентами

Telegram-бот и пайплайн: еженедельно собирают условия по рознице в
Луганской Народной Республике, сравнивают Сбер с ПСБ, ВТБ, ГенБанком и
ЦМР, показывают светофор и выгружают свод в Excel, PDF и HTML.
Встроенный AI-консультант отвечает по собранным цифрам.

---

## Что бот умеет

```
/start
  Сравнить Сбер и ПСБ          сводка по одному конкуренту
  Сравнить Сбер и ВТБ
  Сравнить Сбер и ГенБанк
  Сравнить Сбер и ЦМР
  Выгрузить общий свод         Excel / PDF / HTML / всё сразу
  AI-консультант               три готовых вопроса или свой
  Обновить данные              сбор по одному банку или по всем
```

Бот отвечает только тем, чьи Telegram ID перечислены в `BOT_ALLOWED_IDS`,
и **без этого списка не стартует**: он показывает внутреннюю аналитику, и
доступ, открытый по умолчанию, был бы плохой настройкой по умолчанию.

---

## Чем берутся данные и что этому мешает

Единого парсера не существует — банки устроены по-разному:

| Банк | Что стоит на пути | Чем берём | Проверено |
|---|---|---|---|
| **ПСБ** | ничего | SSR-состояние в HTML, обычный запрос | ✅ |
| **ЦМР** | ничего | чтение отрисованной страницы | ✅ |
| **Сбер** | JS-проверка F5 (`bobcmn` в ответе) | браузер | ❌ |
| **ГенБанк** | Qrator: 401 и скрипт `qauth.js` | браузер | ❌ |
| **ВТБ** | SPA, условия приходят отдельными запросами | браузер | ❌ |

Браузер здесь не обходит защиту: Playwright запускает настоящий Chromium,
который проходит ту же проверку, что и браузер обычного посетителя, и
открывает ту же публичную страницу. Подписи не подделываются, закрытые API
не трогаются.

### Про столбец «Проверено»

Отмечены только те банки, чей сбор подтверждён на живых данных. Сбер, ВТБ
и ГенБанк написаны по разобранной структуре их сайтов, но в окружении, где
писался код, их проверки не проходили из-за прокси — и выдавать
неподтверждённый сбор за рабочий нельзя.

Поэтому они **выключены** в `config/settings.yaml`. Порядок включения:

```bash
python run.py check-bank sber      # покажет, что извлеклось
```

Если ставки сходятся с сайтом — включи банк в настройках и поставь
`verified = True` в его адаптере (`src/banks/others.py`). Пока флаг не
снят, отчёт и бот помечают цифры этого банка как неподтверждённые.

## Установка

### Вариант 1. Docker — проще всего на сервере

```bash
git clone <репозиторий> /opt/bank-compare
cd /opt/bank-compare
cp .env.example .env && nano .env    # токен, список ID, ключ Anthropic

docker compose up -d --build
docker compose logs -f bot
```

Образ уже содержит браузер и корневой сертификат НУЦ Минцифры. Сбор
запускается по понедельникам в 07:00 отдельным контейнером, чтобы бот
отвечал и во время сбора.

### Вариант 2. systemd — если Docker не нужен

```bash
sudo apt install -y python3-venv python3-pip
sudo useradd -r -m -d /opt/bank-compare bank
sudo -u bank git clone <репозиторий> /opt/bank-compare
cd /opt/bank-compare

sudo -u bank python3 -m venv .venv
sudo -u bank .venv/bin/pip install -r requirements.txt
sudo -u bank .venv/bin/playwright install --with-deps chromium

sudo -u bank cp .env.example .env
sudo -u bank nano .env

sudo cp deploy/*.service deploy/*.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now bank-compare-bot
sudo systemctl enable --now bank-compare-collect.timer
```

Проверка: `systemctl status bank-compare-bot` и `journalctl -u bank-compare-bot -f`.

### Сертификат НУЦ Минцифры

Сайты ПСБ и ряда других банков используют сертификат Минцифры, которого нет
в стандартном наборе. Без него Python падает с `CERTIFICATE_VERIFY_FAILED`,
а браузер не открывает страницу.

Корень лежит в `certs/` и подхватывается Python автоматически. **Браузеру
нужен отдельный шаг** — у Chromium своё хранилище:

```bash
sudo cp certs/russian_trusted_ca.pem /usr/local/share/ca-certificates/russian.crt
sudo update-ca-certificates

sudo apt install -y libnss3-tools
certutil -d sql:$HOME/.pki/nssdb -A -t "C,," -n "russian-ca" \
         -i /usr/local/share/ca-certificates/russian.crt
```

В Docker это уже сделано. Если поставить сертификат не получается, есть
аварийный выход — `browser.ignore_https_errors: true` в настройках, но он
ослабляет проверку подлинности сайта, и лучше им не пользоваться.

### Локально, для разработки

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # macOS / Linux
pip install -r requirements.txt
playwright install chromium
```

### Запасной путь: данные из файла

Сбор с сайта может не пойти — банк сменил вёрстку, проверка перестала
проходить, сайт лежит. Чтобы это не останавливало весь отчёт, любой банк
переводится на выгрузку:

```yaml
banks:
  sber:
    enabled: true
    source: "data/sber.xlsx"    # задан — значит на сайт не ходим
```

Поддерживаются `.xlsx`, `.csv`, `.json`. Колонки распознаются по
синонимам, регистр и точная формулировка не важны:

| Поле | Как может называться |
|---|---|
| Ключ | `Ключ`, `Код`, `ID`, `Артикул` |
| Название | `Продукт`, `Название`, `Наименование` |
| Категория | `Категория`, `Тип`, `Группа` |
| Ставка | `Ставка`, `Процентная ставка`, `Ставка, %` |
| ПСК | `ПСК`, `Полная стоимость кредита` |
| Сумма | `Сумма`, `Лимит`, `Сумма кредита` |
| Срок | `Срок`, `Срок кредита`, `Срок вклада` |
| Акция | `Акция`, `Спецпредложение`, `Промо` |
| Ссылка | `Ссылка`, `URL`, `Источник` |

Шаблон с нужными колонками — `data/sber_example.xlsx`. Нераспознанные
колонки не теряются: они попадают в карточку продукта как дополнительные
условия. Если обязательную колонку распознать не удалось, инструмент
**скажет об этом в логе**, а не подставит правдоподобное значение.

## AI-консультант

Модель получает **только факты из нашей базы** — ставки, дельты, акции — и
отвечает на их основе. Общие знания о банках не привлекаются: они
устаревают, а цифры идут первому лицу. Если данных для вывода мало, модель
обязана сказать об этом прямо, а не заполнить пробел правдоподобной
выдумкой.

Модель по умолчанию — `claude-opus-5`. Один запрос стоит копейки: в промпт
уходит выжимка на пару тысяч токенов, а не весь каталог.

### Ключ не от Anthropic напрямую

Карты российских банков Anthropic часто отклоняет, поэтому ключ нередко
покупают у посредника. Такой ключ работает — укажи его адрес:

```ini
ANTHROPIC_API_KEY=sk-star-...
ANTHROPIC_BASE_URL=https://адрес-посредника
AI_MODEL=claude-sonnet-5
```

Модель тоже задаётся явно: у посредников набор свой, и `claude-opus-5`
там может отсутствовать. Если модели нет, бот так и скажет и предложит
посмотреть список у поставщика.

Расширенные параметры запроса (adaptive thinking, уровень усилий) посредник
может не поддерживать. При отказе по форме запроса инструмент сам повторяет
попытку без них — ответ выйдет проще, но кнопка продолжит работать.

Без ключа кнопка отвечает понятной ошибкой, а не падает.

## Сопоставление продуктов

Это самое важное место, и оно намеренно ручное.

В отчёт попадают **только пары из `config/product_map.yaml`**. Автоматический
матчинг по названию работает как подсказка и формирует черновик, но сам в
отчёт не идёт: «Кредит наличными» ПСБ и «Потребительский кредит» Сбера похожи
по названию, но могут отличаться условиями допуска. Цена ошибки — неверная
цифра в отчёте у руководителя.

Порядок работы:

```bash
python run.py suggest
# → data/pairs_suggested.yaml — черновик, отсортирован по похожести
```

Проверяешь глазами, переносишь подтверждённые пары в `config/product_map.yaml`.

```yaml
pairs:
  - psb: /personal/loans/kredit-nalichnymi
    sber: sber_cash
    label: Кредит наличными
    category: Кредиты
```

> **Важно про `category`.** Для «Вклады», «Накопительные счета» и
> «Долгосрочные сбережения» выгодой клиента считается ставка **выше**,
> для кредитных продуктов — **ниже**. Без правильной категории светофор
> покрасит вклады наоборот.

## Светофор

Дельта считается как **ставка Сбера минус ставка ПСБ**, с позиции Сбера:

| Цвет | Значение | Условие по умолчанию |
|---|---|---|
| 🟢 Выигрываем | Сбер выгоднее клиенту | дельта в пользу Сбера, больше 0,5 п.п. |
| 🟡 Паритет | Разница несущественна | менее 0,5 п.п. в любую сторону |
| 🔴 Проигрываем | ПСБ выгоднее клиенту | отставание от 1,0 п.п. |
| ⚪ Нет данных | Сравнение невозможно | не извлеклась ставка или нет пары |

Пороги меняются в `config/settings.yaml` → `thresholds`.

---

## Что считается изменением

Сравнивается с предыдущим успешным сбором:

* **Движение ставки** — сдвиг от 0,25 п.п. помечается как важный;
* **Новая акция** и **завершение акции** — важное;
* **Новый продукт** и **уход продукта** из линейки;
* **Правка условий** в тарифной таблице (сумма, срок, ПСК, требования).

---

## Ограничения, о которых нужно знать

1. **Ставка «от»** — это минимальная заявленная ставка с сайта. Фактическая
   определяется индивидуально, поэтому в отчёте есть дисклеймер и ссылка
   на первоисточник по каждому продукту.
0. **Разбор по тексту грубее разбора по структуре.** У ПСБ условия лежат
   в структурированном состоянии страницы, и это лучший случай. У остальных
   банков приходится читать то же, что видит человек. Такой разбор
   сознательно осторожен: он пропускает продукт чаще, чем выдумывает —
   в отчёте первому лицу пропуск дешевле вымысла.
2. **Кредиты ПСБ не дифференцируются по региону** — проверено, условия в
   Москве и Луганске совпадают. Региональность реально работает по вкладам.
3. **Часть страниц — разделы-лендинги**, а не продукты. Такие страницы в
   отчёт не попадают: фильтр отсекает всё, где нет ни одного условия.
4. **Изменение вёрстки сайта** сломает сбор. Диагностика: `python run.py check`
   покажет, что каталог пуст или состояние не найдено.

## Тонкости, которые заложены в логику

### Какую границу ставки сравниваем

Банк рекламирует кредит как «ставка **от** 16,9%», а вклад — как «**до** 13,8%».
Клиент сравнивает именно эти витринные цифры, поэтому:

* по кредитным продуктам сравнивается **нижняя** граница диапазона;
* по вкладам, накопительным счетам и долгосрочным сбережениям — **верхняя**.

Категория берётся из `product_map.yaml`, так что ошибка в ней приведёт
к сравнению разных концов диапазона. Проверяй категорию при заполнении пар.

### Ставки по вкладам собираются из таблиц

У вкладов условия лежат не в тарифной таблице, а в сетке «срок × сумма».
Здесь две ловушки, обе обойдены:

* **Минимальная гарантированная ставка (МГС)** считается по другим правилам
  и всегда ниже витринной. Она отсеивается на уровне строки и колонки, а не
  по заголовку таблицы: в шапке ПСБ нередко названы обе метрики сразу, и
  фильтр по заголовку выбросил бы таблицу целиком вместе со ставками.
* **Колонка со ставками определяется по содержимому, а не по названию.**
  У одного вклада колонки подписаны «Срок вклада 32 дня», у другого просто
  «32 дня», а шапка «СУММА/СРОК ВКЛАДА» ложно срабатывает на слово «срок»
  и выдаёт колонку сумм за колонку ставок.

К витринной ставке отчёт всегда показывает условия, при которых она
достигается. Это не украшение: «31% годовых» и «31% на 32 дня при сумме
до 50 000 ₽» — принципиально разные предложения, и без второй половины
акционный вклад сравнивается с обычным срочным как равный.

### Акции: что считается действующим

В отчёт попадают только действующие предложения. Завершившиеся отсеиваются
и в отчёт не выводятся вовсе: прошлогодние условия решений не меняют.
Их количество видно в логе запуска, а сами они остаются в базе.

Предложение считается завершившимся, если:

* в тексте стоит «акция завершена / окончена»;
* указана дата окончания в прошлом **с явным годом**.

Без года дату не трактуем: «до 31 октября» может означать и прошлый год,
и будущий, а ошибка здесь дорога в обе стороны.

**Дата рядом с предложением — ещё не его срок.** Формулировка «для владельцев
карт, полученных до 31 января 2024» описывает условие участия, а не окончание
акции. Поэтому дата засчитывается только рядом со словом о сроке
(«действует до», «успейте», «оформите до») и не засчитывается после
причастий вроде «полученных», «оформленных», «выпущенных».

### Акции: омоним «акции»

Слово «акция» означает и предложение, и ценную бумагу. Из-за этого в выборку
попадали статьи инвестиционного раздела — «Что такое акции», «Когда растут
цены на акции», «Как заработать на акциях». Они отсеиваются по
вопросительно-обучающей форме заголовка, вместе с объявлениями вроде
«Мы продлили срок действия карт».

### Акции: как сравниваются

Предложения группируются по сегментам. Сегмент определяется по разделу
сайта — он точнее текста, потому что «кешбэк на такси» встречается и у
дебетовой карты, и у кредитной. Если акция лежит в корне `/personal` и к
продукту не привязана, она попадает в «Кешбэк и бонусные программы» по типу
выгоды: приписывать ей продукт наугад — это выдумка, а группировка по сути
предложения позволяет сравнить её со сберовской корректно.

**Отсутствие акции — не отсутствие продукта.** На страницах вкладов ПСБ нет
промо-баннеров, но сами вклады идут под 31% годовых. Вывод «у ПСБ нет ни
одного предложения» был бы прямым обманом, поэтому когда размеченных акций
у банка нет, сравнение опирается на **витрину продуктов** — лучшие условия
сегмента по данным тарифных таблиц. В отчёте это подписано явно.

Витринная ставка берётся той же границей, что и в основной таблице:
«до» для вкладов и накопительных счетов, «от» для кредитных продуктов.

Внутри сегмента сравнивается **однотипная выгода в одинаковых единицах**:

* кешбэк в процентах — с кешбэком в процентах;
* кешбэк в рублях — с кешбэком в рублях;
* ставка — со ставкой.

Сопоставлять «30% кешбэка» с «9000 ₽ кешбэка» нельзя: это величины разной
природы, и вердикт по их максимуму не значил бы ничего. Если сопоставимой
пары нет, сегмент помечается «не сравнить», а не подгоняется под цвет.

**Розыгрыши в зачёт не идут.** «Розыгрыш 1 000 000 ₽» достаётся одному
человеку и выгодой всем клиентам не является — иначе он перевешивал бы
реальный кешбэк 30% и вставал первым в сегменте. Розыгрыши показываются,
но в конце списка и вне сравнения.

### Узлы карты сайта без страниц

Карта сайта — это дерево CMS, часть узлов служебные и страницы под ними нет.
Такие адреса дают 404, инструмент их тихо пропускает и пишет в лог итоговое
число. Это норма, а не сбой.
