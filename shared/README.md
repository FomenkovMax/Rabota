# Кадровый движок трибьют-страниц

Две страницы — `kaneki/` и `guts/` — построены по структуре
[itachi-референса](https://meghamittal0920.github.io/itachi/) и делят один движок.
Отличаются только контентом, палитрой (`theme.css`) и кадрами.

```
shared/base.css     раскладка и структура; цвет и шрифты берутся из токенов
shared/engine.js    весь рантайм; не знает ни одного имени персонажа
shared/frames.cjs   нарезка ролика в пронумерованные JPEG
kaneki/ guts/       index.html + theme.css + frames/main + frames/eyes
```

## Почему видео, а не набор картинок

Механика первого акта — перемотка кадровой последовательности скроллом. Для этого
нужны десятки кадров, на которых персонаж **не плывёт**. Отдельные генерации этого
не дают, поэтому конвейер такой:

1. `generate_image` — два опорных кадра: «до» и «после» превращения;
   второй генерируется с первым в `medias`, чтобы сохранить лицо, кадрирование и свет;
2. `generate_video` (**kling3_0**, `start_image` + `end_image`) — 5 секунд, которые
   интерполируют превращение целиком;
3. `shared/frames.cjs` — 71 кадр для первого акта, 51 для второго.

Второй акт — тот же приём, но проход взгляда слева направо: индекс кадра берётся
не из скролла, а из X-координаты курсора.

```bash
node shared/frames.cjs clip.mp4 kaneki/frames/main 71 1280 6
node shared/frames.cjs clip.mp4 kaneki/frames/eyes 51 1280 6 1156:626:60:14
#                                                   ^count ^width ^-q:v ^crop W:H:X:Y
```
Кроп нужен, когда генератор запекает в ролик рамку: растянутый на весь экран
леттербокс выглядит как поломка.

## Конфиг страницы

`window.SITE` объявляется в `index.html` до подключения движка:

```js
window.SITE = {
  main:  { count: 71, dir: 'frames/main/', maxUp: 2.2 },  // maxUp — предел зума в drawCover
  eyes:  { count: 51, dir: 'frames/eyes/', maxUp: 2.6 },
  titleWindow: [-1, 0, 0.05, 0.16],   // окна прозрачности: fade in [a,b], hold, fade out [c,d]
  phases: [ /* по одному окну на подпись акта I */ ],
  readout: (x, y, frame) => '…',       // строка счётчика во втором акте
  audio: { cutoff: 300, voices: [{ type, freq, gain }] }
};
```

Палитра приходит из `theme.css`; движок читает `--accent-hot` и `--accent-deep`
через `getComputedStyle`, поэтому частицы, шлейф и разряды окрашиваются сами.

## Что делает движок

- **Прелоадер** гейтится только кадрами первого акта; второй акт догружается
  фоном, поэтому страница открывается раньше, чем при загрузке всего сразу.
- **Акт I** — `renderScrub`: индекс кадра = прогресс секции; подписи гаснут по окнам.
- **Акт II** — `renderEyes`: индекс кадра = X курсора со сглаживанием, плюс
  несколько пикселей вертикального параллакса (кадры вертикаль не отыгрывают).
  На `hover: none` взгляд ведёт себя сам.
- **Устойчивость** — `frameAt()` берёт ближайший загруженный кадр, так что один
  битый файл не гасит сцену.
- **Окружение** — частицы по кромке, разряды из генерируемого SVG-path, шлейф
  курсора, звук синтезируется WebAudio (аудиофайлов нет).
- `prefers-reduced-motion` убирает разряды, частицы и кастомный курсор; скраб
  остаётся, потому что это прямая реакция на действие пользователя.
