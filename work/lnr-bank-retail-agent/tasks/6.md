# Task 6: Адаптеры банков: каталог, документы, инфраструктура, калькуляторы

## Description

Реализовать адаптеры SBER, VTB, PSB, TBANK: продуктовая линейка блоков MVP с доступностью в ЛНР, страницы продуктов и PDF-тарифы, офисы и банкоматы по городам ЛНР, калькуляторы для сценариев DEP и MTG. Сохранить по каждому банку фикстуры для офлайн-тестов и для промптов задачи 7.

Решения tech-spec: D-1, D-7, D-10.

## Acceptance Criteria

- [ ] Общий интерфейс адаптера: `catalog(block)`, `fetch(product)`, `infrastructure()`, `calculate(scenario)`; использует браузер и привязку из задачи 5.
- [ ] Каталог для DEP, CARD, LOAN, MTG: продукты с `product_id` по правилу Data Models и `available_in_lnr` (yes/no/unknown) с источником.
- [ ] Страницы и PDF сохраняются через хранилище с sha256 и `region_method`.
- [ ] CHANNEL: офисы (полноформатные, МФЦ, мобильные) и банкоматы по городам ЛНР из официальных поисков офисов.
- [ ] Калькуляторы DEP-1, DEP-2, SAV-1, MTG-1, MTG-2 заполняются только суммами, сроками и регионом; нет калькулятора или он недоступен → `None`, сценарий уйдёт в формулы.
- [ ] Ошибка одного банка не останавливает остальные: статус и причина в результате.
- [ ] Фикстуры: не меньше 4 страниц или PDF на блок MVP по каждому банку в `tests/fixtures/{bank}/`.

## TDD Anchors

- Офлайн: адаптер PSB на сохранённой странице каталога вкладов возвращает продукты со стабильными `product_id`.
- Офлайн: страница с `Луганск` в списке офисов → строка инфраструктуры с городом.
- Падение fetch одного продукта → остальные собраны, ошибка записана.
