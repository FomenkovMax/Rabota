# Task 2: Хранилище срезов

## Description

Реализовать SQLite-хранилище по разделу Data Models: таблицы данных из системного промпта, `runs`, `raw_documents`, `llm_cache`. Срезы только дописываются — на этом стоит конвейер с историей.

Решения tech-spec: D-8.

## Acceptance Criteria

- [ ] Схема создаётся идемпотентно при первом подключении; включён WAL.
- [ ] Есть все таблицы Data Models; `conditions` уникальна по (`snapshot_date`, `product_id`, `parameter`).
- [ ] API репозитория: начать/завершить запуск, записать продукты/условия/сценарии/инфраструктуру/банки, сохранить сырой документ (путь + sha256), получить последний и предыдущий срез, читать и писать `llm_cache`.
- [ ] Запись в уже завершённый срез запрещена (ошибка).
- [ ] Очистка сырых документов старше N срезов (настройка retention) не трогает разобранные данные.
- [ ] Все запросы параметризованы, без форматирования SQL строками.

## TDD Anchors

- Два среза → `previous_snapshot()` возвращает первый.
- Дубликат (`snapshot_date`, `product_id`, `parameter`) → IntegrityError.
- Retention 1: после двух срезов файлы первого удалены, строки `conditions` первого на месте.
- `llm_cache` возвращает сохранённый ответ по (sha256, prompt_version, model) и None при другой версии промпта.
