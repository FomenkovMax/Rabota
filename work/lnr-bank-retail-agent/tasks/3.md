# Task 3: Формулы сценариев и правила качества

## Description

Реализовать формулы сценариев MVP и правила качества данных. Формулы нужны там, где калькулятор банка не автоматизирован (D-10), правила — чтобы непроверенные значения не попадали в сравнение (D-3).

Решения tech-spec: D-3, D-10.

## Acceptance Criteria

- [ ] Формулы: аннуитетный платёж и переплата; доход по вкладу с ежемесячной капитализацией и без; эффективная ставка; годовая выгода дебетовой карты (базовый кэшбэк с лимитом + % на остаток − обслуживание); годовая стоимость кредитной карты (обслуживание + комиссия за снятие + проценты при потере льготного периода).
- [ ] Сценарии DEP-1, DEP-2, SAV-1, DC-1, CC-1, CL-1, CL-2, CAR-1, MTG-1, MTG-2 читаются из `settings.yaml`; результат помечается `calc_method = agent_formula`, допущения — в `assumptions`.
- [ ] Нехватка входных параметров → результат «н/д» с перечнем недостающих, без подстановок.
- [ ] Правила качества: обязательные поля (`source_url`, `collected_at`, `region_method`, `evidence`); ПСК ≥ номинальной ставки; вклад > ключевая + 3 п.п. и кредит < ключевой без госпрограммы → флаг «перепроверить»; покрытие = собранные / запланированные параметры по банку и блоку.
- [ ] Функция `is_comparable(value)` исключает `not_confirmed` и `confidence = low`.

## TDD Anchors

- Аннуитет 300 000 ₽, 3 года, 20 % → эталонный платёж с точностью до 1 ₽.
- Вклад 1 000 000 ₽, 12 мес, 14 % с капитализацией → эталонный доход до 1 ₽; без капитализации — 140 000 ₽.
- Дебетовая карта: кэшбэк ограничивается лимитом.
- ПСК < ставки → нарушение правила; строка без `evidence` → нарушение.
- `is_comparable` → False для `not_confirmed` и `low`.
