# Task 8: Оркестрация конвейера и анализ

## Description

Собрать режимы `run --mode block|full|update` и `build`: сбор → извлечение → сценарии → качество → срез → изменения и алерты → позиция Сбера и светофор → выводы по шаблонам → `run_log.md`. Добавить блокировку параллельных запусков и итоговый статус для уведомлений.

Решения tech-spec: D-3, D-11, D-16, D-17.

## Acceptance Criteria

- [ ] `block` — этапы 0–5 для одного блока; `full` — все блоки MVP; `update` — полный сбор + изменения + алерты; `build` — только пересборка из БД.
- [ ] Сценарии: результат калькулятора банка, иначе формула; метод записан.
- [ ] Изменения сравниваются с предыдущим срезом по (`product_id`, `parameter`); алерт по порогам из настроек, а также появление/закрытие продукта и новый банк.
- [ ] Gap-анализ только по сравнимым значениям: место Сбера, отклонение от лучшего и медианы, статус (лидер, в рынке, отстаёт, нет у Сбера, нет ни у кого), светофор «блок × банк»; направление по `better`.
- [ ] Выводы — по шаблону «факт + цифра + источник», без LLM.
- [ ] Результат `check` (задача 5) записывается в `banks` и `infrastructure` текущего среза.
- [ ] Lock-файл: второй запуск завершается сразу с кодом ≠ 0 и сообщением.
- [ ] `run_log.md`: режим, банки, блоки, покрытие, алерты, что не удалось и почему; статус запуска ok/partial/failed.

## TDD Anchors

- Ставка 14,0 → 14,3 → алерт; 14,0 → 14,2 → без алерта (порог 0,25).
- Продукт пропал → алерт «закрыт».
- Значение `not_confirmed` не участвует в рейтинге.
- Сбер лучший по вкладу → «лидер»; хуже медианы на 0,6 п.п. → «отстаёт»; для кредита меньше = лучше.
- Шаблон вывода совпадает с примером из tech-spec.
- Второй одновременный запуск получает ошибку блокировки.
- Офлайн-конвейер на фикстурах с моком LLM создаёт срез с данными по всем этапам.
