# Task 4: LLM-провайдер и конвейер извлечения

## Description

Сделать сменный интерфейс LLM, реализацию на GigaChat и конвейер извлечения с защитами от выдумок, prompt-injection и кэшем. Это единственное место, где LLM влияет на данные. Промпты подключаются по контракту D-19; до задачи 7 используются заглушки.

Решения tech-spec: D-4, D-5, D-9, D-14, D-19.

## Acceptance Criteria

- [ ] Интерфейс `LLMProvider.extract(text, block, schema) -> ExtractionResult`; GigaChat-реализация на SDK `gigachat` с `credentials`, `scope`, `model` из настроек и `ca_bundle_file` = CA-бандл.
- [ ] Модель по умолчанию — старшая из `get_models()`, если в настройках не задана; структурированный ответ через `response_format` (json_schema), при неподдержке — через `functions`.
- [ ] Очистка: HTML → текст с таблицами в markdown; PDF → текст через pdfplumber; обрезка до релевантных разделов с логом `tokens_count`.
- [ ] Текст источника передаётся как данные внутри разделителей; у модели нет инструментов.
- [ ] Валидация: только параметры из `parameters.yaml` для блока, корректная единица, числовое значение или «н/д».
- [ ] Проверка цитат: цитата после нормализации пробелов и неразрывных пробелов — подстрока источника, иначе значение отбрасывается.
- [ ] Невалидный ответ — один повтор с текстом ошибки, затем «н/д» с причиной.
- [ ] Кэш по (sha256 очищенного текста, версия промпта из первой строки файла, модель): повтор без вызова LLM.
- [ ] Ключ и токен не попадают в логи.

## TDD Anchors

- Мок LLM возвращает цитату, которой нет в тексте → значение отброшено.
- Мок возвращает неизвестный параметр → отброшен; невалидный JSON дважды → «н/д».
- Тот же текст второй раз → 0 вызовов мока.
- Смена версии промпта → кэш промахивается.
- Нормализация: «14,2 %» с неразрывным пробелом находится в источнике.
