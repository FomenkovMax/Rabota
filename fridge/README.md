# Что приготовить — счётчик калорий по фото холодильника

Веб-приложение: вы фотографируете содержимое холодильника, оно распознаёт продукты,
оценивает их массу и калорийность и предлагает блюда, которые из этих продуктов можно
приготовить, с КБЖУ на порцию и пошаговым рецептом.

Распознавание и подбор делает модель Claude (`claude-opus-5`) с поддержкой зрения.
Ключ API живёт только на сервере — браузер обращается к своему бэкенду, а не к API напрямую.

## Что умеет

- До 4 фотографий за раз (полки, дверца, морозилка) — обрабатываются вместе.
- Таблица продуктов: количество, масса, ккал/100 г, ккал всего, пометка «распознано неуверенно».
- Суммарная калорийность содержимого холодильника.
- 3–8 блюд с сортировкой по калорийности, времени и белку и фильтром «только без докупок».
- Настройки: число порций, приём пищи, тип питания (веган, низкоуглеводное, без глютена и т. д.),
  целевая калорийность порции, произвольные пожелания.
- Съёмка прямо с камеры телефона, drag & drop, вставка из буфера. Фото ужимаются в браузере
  до 1600 px по длинной стороне — трафик и стоимость запроса меньше, качество распознавания не страдает.

## Запуск без терминала

1. Установите **Node.js** (версия LTS) с [nodejs.org](https://nodejs.org/) — это делается один раз.
   На Windows 10/11 можно этого не делать заранее: запускатор сам предложит установить
   Node.js через штатный `winget`, надо будет только согласиться.
2. Откройте папку `fridge` и запустите двойным кликом:
   - **Windows** — `Запустить-Windows.bat`
   - **macOS** — `Запустить-Mac-Linux.command`
     (при первом запуске: правый клик по файлу → «Открыть» → «Открыть», иначе macOS
     не пустит незнакомый файл)
   - **Linux** — тот же `Запустить-Mac-Linux.command`; в свойствах файла отметьте
     «Разрешить выполнение как программы»
3. Откроется чёрное окно и следом браузер со страницей приложения. Первый запуск дольше:
   доустанавливаются зависимости.
4. На странице раскроется блок **«Настройка доступа»** — вставьте туда ключ API
   ([console.anthropic.com → API keys](https://console.anthropic.com/settings/keys))
   и нажмите «Сохранить и проверить». Ключ сохранится в `.data/settings.json` рядом
   с приложением, вводить его каждый раз не нужно.
5. Дальше — фотографируете холодильник, загружаете, получаете результат.

Чтобы закрыть приложение — закройте чёрное окно. Чтобы запустить снова — тот же двойной клик.

**С телефона.** В чёрном окне есть строка вида `http://192.168.1.42:5180` — откройте этот
адрес на телефоне в той же Wi-Fi-сети, и можно снимать холодильник прямо камерой телефона.
Ключ при этом менять можно только на самом компьютере.

Посмотреть интерфейс без ключа и без обращений к API (демо на готовом примере):

```bash
npm run demo
```

## Запуск из терминала

```bash
cd fridge
npm install
npm start                                # http://localhost:5180
```

Ключ можно задать переменной окружения — тогда блок «Настройка доступа» не нужен:

```bash
export ANTHROPIC_API_KEY=sk-ant-...
```

## Переменные окружения

Всё, что задано в окружении, главнее настроек из интерфейса.

| Переменная            | По умолчанию     | Зачем                                                          |
| --------------------- | ---------------- | -------------------------------------------------------------- |
| `ANTHROPIC_API_KEY`   | —                | Ключ API. Если не задан — берётся из `.data/settings.json`.     |
| `ANTHROPIC_MODEL`     | `claude-opus-5`  | Модель. `claude-sonnet-5` дешевле и быстрее, точность ниже.     |
| `FRIDGE_EFFORT`       | `high`           | Глубина рассуждений: `low`, `medium`, `high`, `xhigh`, `max`.   |
| `FRIDGE_MAX_TOKENS`   | `32000`          | Потолок ответа. Уменьшать, если не нужны длинные рецепты.       |
| `FRIDGE_RATE_LIMIT`   | `10`             | Запросов в минуту с одного IP.                                  |
| `FRIDGE_DEMO`         | —                | `1` — демо-режим, модель не вызывается.                         |
| `FRIDGE_NO_OPEN`      | —                | `1` — не открывать браузер при запуске.                         |
| `PORT` / `HOST`       | `5180` / `0.0.0.0` | Где слушать. Занятый порт — не ошибка, берётся следующий.      |

## Как устроено

```
Запустить-Windows.bat        двойной клик: проверка Node, установка зависимостей, старт
Запустить-Mac-Linux.command  то же для macOS и Linux
public/                      интерфейс: чистые HTML + CSS + ES-модуль, без сборки
server.js                    HTTP-сервер: статика, API, лимит частоты, открытие браузера
src/analyze.js               разбор запроса, промпт, вызов модели, нормализация ответа
src/schema.js                JSON-схема результата (structured outputs)
src/settings.js              ключ и параметры модели в .data/settings.json
src/demo.js                  фиксированный ответ для демо-режима
netlify/functions/           те же эндпоинты как serverless-функции
```

Один запрос к API: фотографии + текстовая инструкция уходят одним сообщением,
ответ жёстко ограничен JSON-схемой (`output_config.format`), поэтому парсить прозу не нужно.
Включено адаптивное мышление и серверный фолбэк на случай отказа классификатора
(`fallbacks: "default"`); если бета недоступна для ключа, запрос автоматически
повторяется без неё. Арифметику сервер перепроверяет сам: сумма калорий по продуктам
и признак «готовится без докупок» пересчитываются из данных, а не берутся у модели на веру.

### API

`GET /api/config` → текущие модель, глубина, откуда взят ключ, справочники для списков

`POST /api/settings` → `{apiKey?, model?, effort?}`, сохраняет настройки и проверяет ключ.
Принимается только с самого компьютера (127.0.0.1), даже если сервер виден в локальной сети.

`POST /api/check` → проверка ключа без генерации токенов (запрос карточки модели)

`POST /api/analyze`

```jsonc
{
  "images": [{ "media_type": "image/jpeg", "data": "<base64 без префикса data:>" }],
  "options": {
    "servings": 2,          // 1–12
    "maxDishes": 5,         // 3–8
    "meal": "dinner",       // any | breakfast | lunch | dinner | snack | dessert
    "diet": "highprotein",  // any | vegetarian | vegan | lowcarb | highprotein | glutenfree | lactosefree
    "kcalTarget": 500,      // 0 — не ограничивать
    "pantry": true,         // соль/масло/специи считать имеющимися
    "onlyAvailable": false, // только блюда без докупок
    "notes": "не люблю рыбу"
  }
}
```

Ответ: `{products[], total_kcal, dishes[], notes, meta}` — структура задана в `src/schema.js`.
Ошибки приходят как `{error, code}` с осмысленным HTTP-статусом.

## Деплой

Приложение — обычный Node-сервер без сборки, разворачивается где угодно:

```bash
ANTHROPIC_API_KEY=sk-ant-... PORT=8080 node server.js
```

Для Netlify в каталоге есть `netlify.toml` и функции: в настройках сайта укажите
Base directory = `fridge`, ключ добавьте в Environment variables. **Но учтите:**
у синхронных функций Netlify жёсткий лимит времени (10–26 с в зависимости от плана),
а разбор фото на `claude-opus-5` с `effort=high` обычно идёт дольше. Для Netlify
ставьте `FRIDGE_EFFORT=low` и 3–4 блюда, а для полноценной работы разворачивайте
`server.js` там, где таймаут не ограничен (VPS, Fly.io, Railway, Render).

## Сколько это стоит

Один разбор — это примерно 3–5 тыс. входных токенов (фото + промпт) и 3–6 тыс. выходных
(рассуждения + JSON). На `claude-opus-5` это порядка 0,1–0,2 $ за запрос. Дешевле:
`ANTHROPIC_MODEL=claude-sonnet-5`, `FRIDGE_EFFORT=medium`, меньше блюд и одно фото
вместо четырёх.

## Точность

Калорийность считается по внешнему виду продуктов и справочным таблицам — это оценка,
а не измерение. Ошибка в массе на глаз легко даёт ±20–30 %. Что помогает:

- снимать при хорошем свете, повернув упаковки этикетками к камере;
- делать отдельный кадр для дверцы и морозилки;
- проверять строки, помеченные жёлтой точкой, — там модель не уверена.

Для медицинских задач (диабет, назначенная диета) взвешивайте продукты, а результат
приложения используйте как ориентир.
